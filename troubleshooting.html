DVWA Shows a 404 Not Found Error

Quick answer: Your DVWA folder path doesn't match the URL, or Apache isn't running.

A 404 usually means Apache isn't serving files from the DVWA folder yet. Confirm you cloned DVWA directly into /var/www/html so the URL matches http://localhost/DVWA exactly — folder names are case-sensitive on Linux, so dvwa and DVWA are different paths. Then confirm Apache is actually running: 

sudo systemctl status apache2

If it's inactive, start it:

sudo systemctl start apache2

"Unable to Connect to the Database" Error

Quick answer: The credentials in config.inc.php don't match your MySQL user.

This happens when the database name, username, or password in DVWA/config/config.inc.php don't match what you actually created in MySQL. Open the config file: 

sudo nano /var/www/html/DVWA/config/config.inc.php

And confirm these values exactly match the database, user, and password you created earlier: 

$_DVWA['db_server'] = '127.0.0.1';
$_DVWA['db_database'] = 'dvwa';
$_DVWA['db_user'] = 'dvwa';
$_DVWA['db_password'] = 'password';

If you're not sure the MySQL user exists, log back into MySQL (mysql -u root -p) and re-run the CREATE USER and GRANT ALL PRIVILEGES commands from the install guide.

DVWA Shows a Blank White Page

Quick answer: A PHP error is being silently suppressed — turn on error display to see it.

A blank page almost always means PHP hit a fatal error but isn't displaying it. Enable error output in php.ini: 

sudo nano /etc/php/8.2/apache2/php.ini

Set (or confirm) this line, then save and restart Apache:

display_errors = On
sudo systemctl restart apache2

Reload the page — the real error should now appear. You can also check the log directly: 

sudo tail -f /var/log/apache2/error.log

Missing PHP Module Errors

Quick answer: Install the missing module and restart Apache.

DVWA needs mysqli, gd, curl, and openssl. Check which are installed: 

php -m

Install anything missing, then restart Apache:

sudo apt install php-mysqli php-gd php-curl php-openssl
sudo systemctl restart apache2

Permission Denied Errors

Quick answer: Apache (www-data) doesn't own or can't write to the DVWA folder.

Re-apply ownership and permissions so Apache can read and write DVWA's files, especially the upload and config directories: 

sudo chown -R www-data:www-data /var/www/html/DVWA
sudo chmod -R 755 /var/www/html/DVWA
sudo chmod -R 777 /var/www/html/DVWA/hackable/uploads
sudo chmod -R 777 /var/www/html/DVWA/config

Login Page Rejects admin / password

Quick answer: You need to click "Create / Reset Database" on setup.php first.

DVWA's default login is username admin and password password — but the account only exists after the database tables have been created. Visit http://localhost/DVWA/setup.php and click "Create / Reset Database", then try logging in again.

Installing DVWA Without Docker

The main install guide sets up DVWA natively using Apache, MySQL, and PHP — no Docker or containers required. DVWA does also ship an official Dockerfile if you'd rather containerize it, but every step in the installation guide works on a plain Ubuntu or Kali install with no Docker involved.

Still Not Working? Full Troubleshooting Checklist

If DVWA still isn't loading correctly after trying the fixes above, work through this list in order:

  • Blank white page: enable PHP error display and check sudo tail -f /var/log/apache2/error.log
  • "Unable to connect to the database": re-check config.inc.php matches your MySQL username and password
  • PHP module errors: install missing modules and restart Apache
  • Permission denied errors: re-apply the ownership commands above
  • Login page rejects admin/password: make sure you clicked "Create / Reset Database" first
  • Still stuck? re-check every step in the installation guide in order — most issues trace back to one skipped or mistyped command
